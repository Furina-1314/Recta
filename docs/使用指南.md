# Recta 矩衡 · 使用指南

高校班委财务审批与分户账管理系统。高确定性、强一致性、严禁模糊账目；所有金额全程整数分运算（禁用浮点），每一笔钱都有单号、经办人与不可变流水。

---

## 1. 安装与首次配置

1. 双击 `Recta-vX.Y.Z-win-x64-Setup.exe` 安装（安装到当前用户目录，无需管理员权限）。
2. 在**安装目录**放置 `.env.local` 文件（由班级管理员提供），内容一行：
   ```
   DATABASE_URL="postgresql://…neon.tech/neondb?sslmode=require"
   ```
   组织内所有人的 `.env.local` **内容相同**——大家连的是同一个数据库，数据实时互通。
3. 空系统首次启动会出现**「系统未初始化」引导面板**：开立首任团支书（系统生成一次性临时口令，请立即抄录），首次登录会被要求修改口令；其后所有账号由团支书在「用户」页开立。

> 安装目录的 `.env.local` 是数据库连接凭据，请妥善保管，不要外传给无关人员。

## 2. 窗口标识：测试库 vs 正式库

| 启动方式 | 窗口标题 | 数据去向 |
| --- | --- | --- |
| 双击桌面的 Recta 矩衡 | `Recta 矩衡` | **生产库**（真实账目） |
| 双击仓库 `scripts\launch-test.bat` | `Recta 矩衡【测试库】` | **测试库**（随便造，不影响生产） |

- **标题带【测试库】的窗口里，正式账号登录不上是正常现象**——测试库与生产库账号相互独立。
- 测试实例带硬保护：即使配置出错也只会启动失败，绝不可能静默连上生产库。
- 重置测试数据：Neon Console → `recta-test` 分支 → Reset from parent，或执行 `db/reset-test.sql`。

## 3. 角色与权限

| 角色 | 开号/管理 | 提单 | 审批 | 办结 | 审计看板 |
| --- | --- | --- | --- | --- | --- |
| 团支书 | ✅ 用户页全部功能 | ✅ | 灵活公款唯一；班费可审 | 灵活公款唯一 | ✅ 全部 |
| 生活委员 | ❌ | ✅ | 系里报销唯一；班费可审 | 系里报销唯一；班费唯一 | 班费与代管相关 |
| 职能班委 | ❌ | ✅ | ❌ | ❌ | 仅本人单据 |

- 账号自保护：团支书**不可停用自己的账号**、**不可重置自己的密码**（改自己密码须验证旧口令）；团支书与生活委员席位各仅一人在任。
- 账号只有"停用"没有删除；停用后立即无法登录，可随时重新启用。

## 4. 各模块功能

### 总览
全班资金状况一屏速览：灵活公款余额、系报销挂账（应收）、代管现金、生委垫资四个数字卡片，以及动账单据状态分布（待审理 / 待办结 / 已办结 / 已驳回）。右上角「刷新」手动更新。

### 审批
所有资金申请的流转中心。

- **新提单**：点右上角「＋ 新提单」弹出窗口，顶部切换**支出提单 / 入账登记**。
  - 支出：选出资渠道（灵活公款 / 系里报销 / 班费平摊）→ 填事项与金额 → 班费平摊需勾选参摊同学（支持全选）并指定尾差承担人，系统实时预演分摊；可附证明材料链接。
  - 入账：选类型（灵活公款增资 / 系报销回款核销 / 同学班费充值）→ 填来源与金额 → 班费充值支持**多选同学批量充值**（每人等额，任一失败整体不生效）。
- **审批**：对待审理单据，可全额核准、核减金额（须填核减原因）、或按预置原因驳回（选"其他"须填补充说明）。**驳回为终态**，需重新提单。
- **办结**：对已核准单据，由对应出纳人「确认办结扣款」——此步才真正动账，系统自动生成含垫资明细的批复。
- 每张单据有全局唯一单号：支出 `REQ-NNNNNN`、入账 `INF-NNNNNN`。

### 账目
全部资金流水的统一台账：支出单据与入账记录合并展示，支持**高级筛选**（流水类型 × 出资渠道 × 单号/事项搜索）。点击任意一条查看完整详情：单号、日期、金额、提单人、审批人与审批意见、办结人与办结批复（含垫资明细）、证明材料链接、班费分摊明细（逐人金额、尾差、垫付标注）。「导出」可将当前筛选结果存为 CSV（Excel 直开）。

### 分户
每位同学的独立班费账户。

- 名单管理（团支书）：录入学号与姓名、改名。
- 点击任意同学查看**历次流水**（日期 / 类型 / 变动 / 变动后余额 / 备注），余额为负表示暂由生活委员垫付，充值补缴后自动恢复。
- 「导出」可导出全班名单与余额，或单个同学的流水。

### 审计
团支书专属统计看板：提单总量、驳回率、核减差额、平均审批/办结响应时长、常见驳回原因 Top 5，以及每位班委的逐人指标（提单 / 驳回 / 办结 / 金额 / 渠道分布 / 时效）。

### 用户
团支书专属账号管理：开立账号（选角色，生成一次性临时口令，可一键复制）、重置密码、改名、停用 / 启用。新账号首次登录必须修改口令。

### 设置
浅色 / 深色主题切换；修改本人口令；查看版本信息。

## 5. 实时同步与断线

- 所有实例共享同一数据库，任何一端的操作会通过变更推送实时反映到其他人的界面。
- 断线时：状态栏红/橙色提示，此时点击操作按钮会立即提示离线，不会无限等待；网络恢复后自动重连并补齐期间错过的数据。
- 每次界面刷新都会做**账目平衡校验**（全班结余 = 代管现金 − 生委垫资），校验异常会醒目提示。

## 6. 常见问题

| 问题 | 说明 |
| --- | --- |
| 登录提示"身份校验失败" | 账号不存在于所连的库，或口令错误。测试实例（【测试库】标题）里没有生产账号，反之亦然。 |
| 启动没有出现引导面板 | 用户表非空（已有账号）。测试库被自动化测试占用时，执行 `db/reset-test.sql` 重置。 |
| 提示"连接超时 / 离线" | 网络或数据库暂时不可达；应用会自动重连，恢复后重试即可。 |
| 程序异常退出 | 查看 `%LOCALAPPDATA%\Recta\logs\crash.log`，反馈时附上该文件。 |
| 导出的 CSV 中文乱码 | 文件为 UTF-8 带 BOM，若用旧版文本编辑器打开请选择 UTF-8 编码；Excel 直接双击正常。 |

## 7. 技术形态（开发者）

- 前端 Avalonia UI 11（.NET 10），核心业务 Modern C++20 编译为原生 `recta_capi.dll`（C ABI + JSON），数据库 Neon PostgreSQL（金额一律 `BIGINT` 分，禁用浮点）。
- 目录：`native/`（C++ 核心：领域 / 存储 / 服务 / C ABI）、`desktop/`（Avalonia 前端与互操作）、`db/schema/`（数据库 DDL）、`scripts/`（辅助脚本）。
- 构建、测试与发布流程见根目录 [README](../README.md)。
